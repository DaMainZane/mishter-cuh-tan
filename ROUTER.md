# Router

Find the files for a task here, then open only those. Do not read whole folders. Search for a symbol before opening a file. File descriptions: `INDEX.md`. Registration methods, hooks and registries: `EXTENSION POINTS.md`. Step-by-step for a new piece, action, addon, tech node or client overlay: `RECIPES.md`; a working example addon to copy: `src/packs/_template/demo.ts`.

Content is data: an addon registers it through `PackApi` (see `EXTENSION POINTS.md`). The engine in `src/shared` should not need edits. The hand-written glue still outside the registry is marked **glue**.

## Glue names

The generated `INDEX.md` rows no longer list these. Taken from the old hand-written rows, not re-checked against the code: search for the name before trusting it.

- `server/socket.ts`: the generic `act` event (any action type, always reports) and `place` event (any piece, runs `build`, always reports). `clickVertex` and `clickEdge` keep only the base clicks (steal victim, settlement to city, new settlement; road, or bridge on an ocean edge). The base game events (`rollDice`, `endTurn`, `discardCards` with `wild` for fish, trades, ...) are still one handler each, on purpose (R6.6 skipped). The nine tech and Tidebound events (`researchTech`, `upgradePort`, `upgradeHarbor`, `upgradeBridge`, `demolishBridge`, `convertTile`, `spendFish`, `feedSea`, `drivePirate`) are gone: the client sends `act` with `research_tech`, `upgrade_port`, `upgrade_harbor`, `upgrade_bridge`, `demolish_bridge`, `convert_tile`, `spend_fish`, `feed_sea`, `drive_off_pirate`.
- Fields sent to the client (since R7a the Tidebound ones come from `VIEW_DATA` entries in the addon files; `pieceCosts` and `wildTokens` are still built in `server/view.ts`): per-player `pieceCosts`, `bridgeUpgradeCost`, `wildTokens` (same visibility as the hand), `netSpots` (sea tile ids, yourself only), `netTiles` (the sea tiles that carry a player's nets, public), `netCost` (yourself only; a net is a tile action, not in `pieceCosts`), `netsLeft`, `feedSpots`, `feedCost`, public `fishIcons`, and `hexOverlays` plus `tide` when Tides is on. Related: `wrecks`, `pirates`, `pirateDrives`.
- `client/render/board.ts`: layers `boardFishLayer`, `boardWrecksLayer`, `boardPiratesLayer`; `clickFeedSpot` (feed mode, `setBuildMode('feed')`) and `clickNetSpot` (net mode, `setBuildMode('net')`; both pick a sea tile and emit `act`: `feed_sea`, `place_net`); `clickEdge` opens the bridge picker; the overlay layer is rewritten only when its markup changes.
- `client/icons.ts`: `fishGroundMarkup` (fish with boost pips), `netTileMarkup` (a net drawn over its sea tile), `wreckMarkup`, the fish token, piece shapes. `client/render/overlay.ts`: `renderElevationMarkup`, flood colors from `--flood-*` tokens.
- `client/render/hand.ts`: `onClickHandWild` (pick a fish for a discard or open the spend sheet). `client/render/drawer.ts`: discard of cards and fish, spend-a-fish sheet.
- `server/main.ts`: `/api/memory/export` and `/api/memory/import`. `server/runtime.ts`: `mapRegistryFor` (room map registry, cached per addon set). `server/rooms.ts`: `rebindPlayerId` (reconnect).
- Names of registries and modifiers (`COST_MODS`, `RATIO_MODS`, `PORT_IDLE_CHECKS`, `HARBOR_RATIO_MODS`, `STEAL_COUNT_MODS`, `DISCARD_LIMIT_MODS`, `SEVEN_STEPS`, ...) are in `EXTENSION POINTS.md`.

## Always

- After adding or changing an addon: `npm run addons`. After adding or changing imports: `npm run headers:write`. After adding, moving or re-describing a file: `npm run index`. Then `npm run typecheck` and `npm test`.
- Layer rules (enforced by `tests/architecture.test.ts`): `shared` imports only `shared`; a pack imports `shared`, itself and `packs/base`; `server` never imports `client`; `client` imports only `client` and `shared`. No new circular imports.
- Behavior-preserving work leaves `tests/golden.snapshot.json` untouched.
